# Implementation Plan: Audit and Verification of PEQ Filter Calculations

**Branch**: `002-audit-peq-filters` | **Date**: 2026-09-03 | **Spec**: [spec.md](spec.md)

**Input**: Feature specification from `/specs/002-audit-peq-filters/spec.md`

## Summary

Build an empirical diagnostic engine (`scripts/audit_peq_filters.py`) and API endpoint (`/api/audit_peq`) that objectively analyzes whether the 7-band parametric EQ filters calculated for the Yamaha RX-V673 and Q Acoustics 3020i accurately target true physical room resonances. The tool evaluates the 14 biquad filters against a composite acoustic baseline (80% Sweet Spot + 20% Spatial Average), detects frequency misalignment (> 5 Hz), flags unphysical positive modal gain (> 0 dB), verifies discrete Yamaha hardware grid snapping, quantifies residual RMS error, and offers automated re-optimization if filters are diagnosed as suboptimal.

## Technical Context

**Language/Version**: Python 3.10+ (running Python 3.14.7 on Linux)

**Primary Dependencies**: `numpy`, `scipy` (signal processing & peak detection), standard library (`json`, `urllib`, `dataclasses`, `unittest`)

**Storage**: Local immutable `.npz` measurement files (`data/medicion_real_calibracion.npz`, `data/medicion_promedio_espacial.npz`), `config/targets.json`

**Testing**: `python3 -m unittest` test suite in `tests/test_audit_peq.py`

**Target Platform**: Linux x86_64, headless CLI + local HTTP/HTTPS daemon (`scripts/web_calibration_server.py`)

**Project Type**: Acoustic signal processing CLI tool and embedded REST API endpoint

**Performance Goals**: Complete full mathematical audit of 14 bands in < 2 seconds; unit test suite executes in < 3 seconds

**Constraints**: Max 7 bands per channel, discrete Yamaha frequencies (28 steps) and Q factors (0.5 to 10.08), zero positive boost below 500 Hz

**Scale/Scope**: 2 audio channels (Left/Right), 7 biquad filters per channel, frequency band 20 Hz to 20 kHz (primary modal focus 40 Hz to 500 Hz)

## Constitution Check

*GATE: Must pass before Phase 0 research. Re-check after Phase 1 design.*

1. **Principle I (Hardware-First — No Simulated State)**: PASS. All acoustic evaluations use empirical `.npz` recordings captured by physical sweep convolution; no synthetic data fallback.
2. **Principle II (Non-Destructive Telemetry)**: PASS. The audit command is strictly read-only and analytical; it does not issue state-changing YNC PUT commands.
3. **Principle III (Profile-Scoped Verification)**: PASS. Target comparisons are strictly scoped by profile key (e.g. `harman_wide_room`) loaded from `config/targets.json`.
4. **Principle IV (Measurement Immutability & Traceability)**: PASS. The audit references immutable existing measurement archives and generates timestamped diagnostic reports without overwriting raw captures.
5. **Principle V (Minimum Viable Command Surface)**: PASS. Re-optimization produces a discrete parameter matrix compatible with atomic Write-Commit-Readback; no scene overrides or unrelated parameter writes.
